# Шпаргалка для защиты (в репозиторий класть не обязательно)

## Что открыть заранее (вкладки в Chrome)
1. Ваш репозиторий на GitHub, вкладка **Code**.
2. Он же, вкладка **Actions**.
3. Страница репозитория, справа блок **Packages**.
4. Нажмите клавишу `.` на вкладке Code: откроется VS Code в браузере, там удобно показывать файлы.

## Сценарий показа (6 шагов из задания)
1. **Изменение → зелёный CI.** Правите любую мелочь (например, строку в README), коммит, push в main. Actions: зелёная галочка.
2. **Образ в Packages.** Packages: образ с тегом `latest`.
3. **Тег.** `git tag v1.0.0` и `git push origin v1.0.0`. В Packages появляется образ `1.0.0`.
4. **Выкат и откат.** Поставьте ещё `v1.1.0` (после небольшого изменения), запустите `1.1.0`, потом откатитесь на `1.0.0` по RUNBOOK. `curl localhost:8000/version` покажет, какая версия работает.
5. **README и RUNBOOK.** Откройте оба файла на GitHub.
6. **Одно решение.** Скажите вслух: «Миграция обратно совместима: только `CREATE TABLE IF NOT EXISTS`, ничего не удаляем. Поэтому старая версия работает с базой, которую уже обновила новая, и откат безопасен для данных.»

## Кто за что отвечает (если спросят про строчки)

### Dockerfile
- `FROM python:3.12-slim`: лёгкий образ с Python.
- `COPY pyproject.toml uv.lock ...` + `RUN uv sync`: зависимости ставятся ДО кода, слой кэшируется.
- `COPY app ./app`: код копируется после зависимостей, он меняется чаще.
- `ARG/ENV APP_VERSION`: версия образа, её передаёт CI.
- `CMD ... --host 0.0.0.0`: сервер слушает все адреса, иначе снаружи контейнера он недоступен.

### .dockerignore
Не копируем в образ `.env` (секреты), `.git` и `.venv` (мусор, большой размер).

### compose.yaml
- `POSTGRES_HOST: db`: сервис находит базу по имени сервиса, а не по localhost.
- `healthcheck` у db: `pg_isready` проверяет, что база готова.
- `depends_on: condition: service_healthy`: app запускается только когда база здорова.
- `volumes: db_data`: данные базы не пропадают при перезапуске.
- `${POSTGRES_PASSWORD}`: пароль берётся из `.env`, в репозитории его нет.

### app/config.py
`BaseSettings` (pydantic-settings) читает настройки из переменных окружения или `.env`. Пароль не прописан в коде.

### app/main.py
- `MIGRATION`: создаёт таблицу `messages`, если её нет (`IF NOT EXISTS`, поэтому обратно совместимо).
- `lifespan`: при старте выполняет миграцию.
- `/health`: быстрая проверка, что сервис жив (база не трогается).
- `/version`: показывает версию образа.
- `GET /messages`, `POST /messages`: читают и добавляют записи в базу.

### .github/workflows/ci.yml
- `on: push / pull_request / tags`: когда запускается.
- job `check`: `ruff` (линтер) и `pytest` (тесты).
- job `publish`: `needs: check` (только после зелёной проверки), `if` (только main или тег vX.Y.Z).
- `docker/login-action` + `GITHUB_TOKEN`: вход в ghcr.io без паролей.
- `metadata-action`: сам формирует теги образа: `latest` для main, `1.0.0` для тега `v1.0.0`.
- `build-push-action`: собирает и публикует образ.

### .env.example и .gitignore
`.env` с реальным паролем в `.gitignore`, в репозитории лежит только `.env.example` без секретов.
